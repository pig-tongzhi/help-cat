# 帮帮小猫「77」高级公益编辑风品牌与首页设计

日期：2026-08-11

状态：视觉方向已由用户确认，待规格审阅

## 1. 项目愿景

“帮帮小猫”面向真实城市救助场景，目标不是制作个人宠物主页，而是建设一个可以长期承载猫咪档案、社区协作、救助任务和公益信任的平台。

77 是平台的品牌原型和第一个完整故事：用户于 2025 年 6 月 2 日（农历五月初七）遇见并救助 77，因此得名。77 的真实经历用于解释“为什么要做这个平台”，但公共内容和产品能力仍服务于所有流浪猫、志愿者与社区。

核心品牌主张：

> 让每一只小猫，都被认真看见。

长期寄语：

> 安得广厦千万间，大庇天下小猫俱欢颜。

## 2. 已确认的设计方向

采用“高级公益编辑部”方向：

- 参考高端品牌官网的克制留白、强图像与清晰层级，不直接仿制任何具体网站。
- 用真实猫咪照片建立信任，用编辑式排版承载故事，用产品数据证明行动。
- 萌宠感来自猫咪本身和少量品牌细节，不使用幼儿化插画、堆叠贴纸或过量渐变。
- 视觉需要同时适配 H5、手机、平板和桌面，并为未来微信小程序复用设计语言。

## 3. 品牌符号：77 极简黑眼斑

### 3.1 造型

以 77 的真实外貌为原型，绘制代码原生矢量符号：

- 正面白色猫脸轮廓。
- 观察者右侧、对应 77 左眼周围的单侧黑色眼斑。
- 小号粉色鼻尖作为唯一暖色细节。
- 耳朵、眼睛和下颌使用最少节点，避免缩小后糊成一团。
- 不使用照片描边、复杂毛发或文字嵌入图标。

### 3.2 使用场景

- 浏览器 favicon：16、32、48 像素。
- Apple Touch Icon / PWA 图标：180、192、512 像素。
- H5 顶部品牌标识和移动端菜单。
- 管理后台左上角返回用户端的品牌入口。
- 微信小程序后续版本的品牌素材基础。

### 3.3 输出要求

- 主文件使用 SVG，提供透明背景 PNG 回退版本。
- favicon 在浅色和深色浏览器标签栏中都应保持可辨识。
- 16×16 像素测试时，首先保住耳朵、黑眼斑和脸部外轮廓；粉色鼻尖允许弱化。
- 图标必须带有无障碍名称；纯装饰实例对读屏隐藏。

## 4. 首页信息架构

### 4.1 顶部品牌栏

桌面端采用单行导航：

- 左侧：77 极简黑眼斑符号 + “帮帮小猫”。
- 右侧：77 的故事、需要帮助、猫咪档案、救助任务。
- 管理员和超级管理员登录后，显示进入管理后台的明确入口。

移动端保留品牌符号与名称，次级入口折叠到菜单；主要任务继续由底部导航承担。

### 4.2 首屏主视觉

首屏使用 77 的清晰正面真实照片，文字与照片形成左右构图；手机端改为图片背景上的安全文字区。

内容层级：

1. 主标题：“让每一只小猫，都被认真看见”。
2. 次级入口：“77 的故事”。
3. 不放虚构营销口号，不让多个按钮竞争注意力。

图片需要独立准备桌面横图和手机竖图裁切，保证 77 的双眼和黑眼斑始终处于视觉安全区。图片采用 WebP/AVIF 优先、JPEG 回退，并提供明确替代文本。

### 4.3 公益数据带

首屏之后展示四类真实指标：

- 已建立档案的猫咪。
- 已完成的救助或找到新家的猫咪。
- 医疗救助记录。
- 已覆盖的小区或有效支持者。

所有数字从真实 API 计算；数据为空时显示 0 或隐藏该指标，不使用概念图中的演示数字。指标需定义统计口径，避免把待审核、测试或已归档数据计入公开成果。

### 4.4 猫咪档案

- 桌面端采用四列编辑式卡片，平板三列，手机两列。
- 卡片固定图片比例和最小高度，不因图片缺失产生大面积空白。
- 优先展示名字、城市/小区、公开状态；紧急程度只在有真实任务时显示。
- 卡片点击进入猫咪详情，不在首页堆叠全部医疗和审核信息。

### 4.5 救助任务

- 与猫咪档案并列但视觉强调更高，突出地点、紧急程度、所需行动和截止时间。
- 紧急状态不只依赖颜色，必须附带文字。
- 已结束任务不混入进行中任务，可进入历史记录查看。

### 4.6 页尾

页尾保留品牌寄语：

> 安得广厦千万间，大庇天下小猫俱欢颜

同时提供隐私说明、联系方式和必要的备案信息位置。

## 5. 77 的故事与真实档案

### 5.1 公共故事页

“77 的故事”采用时间线而非普通猫咪详情页：

1. 2025-06-02：相遇与救助。
2. 幼猫期：喂养、检查和逐步恢复。
3. 成长期：进入家庭、性格与生活变化。
4. 今天：77 成为帮帮小猫的品牌原型。

页面只使用经过筛选和优化的照片；视频首屏不自动播放。含明显人物面部、私人室内细节、设备信息或地理线索的素材在公开前需要裁切、模糊或不使用。

### 5.2 平台猫咪档案

77 同时作为真实猫咪档案写入系统，而不是只做静态专题：

- 名称：77。
- 相遇日期：2025-06-02。
- 命名由来：农历五月初七。
- 花色特征：白底黑斑、单侧黑眼斑。
- 当前状态、性别、绝育、疫苗、健康和所在地等未确认字段不得从照片推断，需由用户资料或后台补充。
- 档案与故事页通过稳定 ID 关联，避免复制两份互相漂移的数据。

## 6. 视觉系统

### 6.1 色彩

- 页面底色：暖白 `#F7F5F1`。
- 卡片表面：`#FFFFFF`。
- 主文字：墨黑 `#171717`。
- 次文字：暖灰 `#6F6B65`。
- 品牌强调：杏橙 `#D9683A`，仅用于主行动、选中态和关键下划线。
- 77 眼斑：近黑 `#111111`。
- 鼻尖：低饱和粉 `#D99386`。

所有颜色通过 CSS 设计令牌维护；状态色与品牌色分离。

### 6.2 排版

- 中文主标题使用高品质宋体/衬线字体栈，营造编辑感；界面文字继续使用清晰的系统无衬线字体。
- 主标题使用 `clamp()` 响应式缩放，手机端最多三行。
- 正文保持舒适行高和受控行宽，不出现全屏超长文本行。
- 数字使用等宽数字特性，避免加载时跳动。

### 6.3 组件与动效

- 边框使用细线和留白，避免多层阴影和玻璃拟态堆叠。
- 卡片圆角克制统一；图片圆角小于容器圆角。
- 页面进入、菜单和卡片反馈控制在 160–280ms。
- 支持 `prefers-reduced-motion`，不使用自动轮播、视差背景或阻塞滚动的动画。

## 7. 响应式与微信小程序兼容

### 7.1 断点原则

- 手机：单列首屏、两列猫咪卡片、底部导航，适配安全区。
- 平板：双区首屏、三列卡片；横竖屏都不能出现横向滚动。
- 桌面：内容最大宽度受控，首屏文字与图片并排，四列档案卡片。

布局以内容变化为断点依据，不绑定某个具体设备型号。

### 7.2 小程序迁移约束

- 不把核心交互依赖于 hover。
- 点击目标不小于 44×44 CSS 像素。
- 上传入口明确区分“从相册选择”和“拍照”；不强制 `capture`。
- 导航、卡片、状态标签和品牌令牌保持可映射到小程序组件。
- 远程图片全部使用 HTTPS，为后续合法域名配置留出统一资源域名。

## 8. 性能、可访问性与可靠性

- 首屏主图提供响应式尺寸，避免手机加载桌面原图。
- 首屏关键资源有尺寸占位，减少布局偏移；非首屏图片懒加载。
- 不依赖外部字体才能显示页面，字体失败时仍保持稳定排版。
- 所有图片具有真实替代文本；装饰图标不重复播报。
- 正文、按钮和状态满足 WCAG AA 级对比度目标。
- 键盘可操作导航和弹层，焦点态清晰，错误信息与字段关联。
- 页面在图片失败、接口空数据、接口超时和未登录状态下均有完整降级。

## 9. 数据与隐私边界

- 首页和故事页只读取公开、已审核内容。
- 精确家庭地址、联系电话、救助人身份和照片元数据不得进入公开页面。
- 上传的原图应在服务端移除 EXIF 信息，并生成公开尺寸副本。
- 用户提供的 77 素材先作为受控源文件保存；公开版本通过人工选择和裁切生成。
- 统计数据不得包含 QA 测试数据。

## 10. 验收标准

### 10.1 视觉

- 首页与确认的概念图保持同一设计语言，但使用真实文案和真实数据。
- 77 极简黑眼斑符号在 16×16、32×32、180×180 和 512×512 下可辨识。
- 手机、平板和桌面无横向溢出、遮挡、过大空白或固定导航覆盖内容。

### 10.2 功能

- favicon、顶部品牌标志和后台返回入口使用同一品牌源文件。
- 77 的公共故事与平台档案均可访问，并共享稳定数据关联。
- 管理员入口只对有权限账号显示，未登录用户不出现错误入口。
- 首页数据来自真实接口，空数据、失败和加载状态均可用。

### 10.3 质量门禁

- 现有 Python、Node 与前端契约测试通过。
- 增加 favicon/manifest、首页结构、角色入口、图片回退和响应式契约测试。
- 在常见手机宽度、平板横竖屏和桌面尺寸执行截图回归。
- 在真实 iPhone Safari/微信内置浏览器或等价设备完成相册上传、导航、安全区和缓存更新验证。
- Lighthouse 或等价检查覆盖性能、可访问性、最佳实践和 SEO；不以单次分数替代真实设备验证。

## 11. 实施边界

第一阶段实现：

- 77 极简黑眼斑 SVG 与多尺寸 favicon。
- 新首页视觉、真实响应式结构和后台品牌统一。
- 77 故事页和真实平台档案关联。
- 选定照片的优化、隐私处理、WebP/AVIF 输出与回退。
- 测试、文档、部署与线上冒烟验证。

第一阶段不实现：

- 自动 AI 识别猫咪或自动生成健康结论。
- 募捐、支付、商城和会员体系。
- 77 视频自动播放或大体积首页背景视频。
- 微信小程序正式发布；本阶段只保证设计和接口兼容基础。

## 12. 发布策略

1. 在独立开发分支完成品牌资产、页面、数据和测试。
2. 使用真实测试数据验证用户、管理员和超级管理员视角。
3. 先部署到可回滚版本目录并完成服务器端健康检查。
4. 切换线上静态资源，使用内容哈希或版本号避免旧缓存。
5. 验证 `https://helpcat.xyz/`、管理后台、favicon、移动端和关键 API。
6. 保留上一个稳定版本，线上异常时执行快速回滚。
