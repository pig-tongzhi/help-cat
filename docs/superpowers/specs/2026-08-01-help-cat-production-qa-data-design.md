# 帮帮小猫生产全流程测试数据设计

## 目标

在生产环境生成一套名称带 `[QA-20260801]` 标识、可验证、可定向清理的测试数据，供超级管理员从后台查看完整业务状态。生成过程不得读取或修改 zack 的密码，不得产生第二个超级管理员，不得覆盖真实数据。

## 方案比较

1. 直接写 SQLite：速度快，但会绕过接口校验、权限与审计，不足以证明全流程可用。
2. 纯 API：最接近真实流程，但超级管理员操作需要 zack 的真实密码，不符合最小凭据原则。
3. API 主导、最小数据库引导：通过公开接口注册测试账号；只在数据库临时签发一个 zack 短期会话，其他操作全部调用生产 API，结束后撤销临时会话。采用此方案。

## 测试身份

- `zack`：保留唯一 `SUPER_ADMIN`，仅使用临时会话执行赋权和审核。
- `qa_admin_20260801`：先注册为 `USER`，再由 zack 通过角色接口提升为 `ADMIN`。
- `qa_user_a_20260801`：普通居民，负责建议小区、提交猫咪和领取任务。
- `qa_user_b_20260801`：普通居民，负责补充其他审核状态和媒体上传。

所有测试账号使用独立强密码；密码仅在最终交付中提供，不写入设计文档或清理清单。

## 状态覆盖

### 小区

- `[QA-20260801] 星河家园`：管理员创建，`ACTIVE`。
- `[QA-20260801] 待审核小区`：普通用户建议，`PENDING_REVIEW`。
- `[QA-20260801] 未通过小区`：普通用户建议后管理员拒绝，`HIDDEN`。
- `[QA-20260801] 已归档小区`：管理员创建后归档，`ARCHIVED`。

### 猫咪

- `[QA-20260801] 待审核橘猫`：普通用户提交，`PENDING_REVIEW + ACTIVE`。
- `[QA-20260801] 已公开奶牛猫`：普通用户提交并审核通过，`APPROVED + ACTIVE`。
- `[QA-20260801] 未通过狸花猫`：普通用户提交后拒绝，`REJECTED + ACTIVE`。
- `[QA-20260801] 已隐藏三花猫`：审核通过后隐藏，`APPROVED + HIDDEN`。
- `[QA-20260801] 已归档黑猫`：审核通过后归档，`APPROVED + ARCHIVED`。
- `[QA-20260801] 管理员录入白猫`：管理员创建，直接 `APPROVED + ACTIVE`，并关联测试图片。

### 任务与媒体

- `[QA-20260801] 小区晚间补粮`：保持 `OPEN`。
- `[QA-20260801] 东门猫窝巡查`：由普通用户领取，变为 `CLAIMED`。
- 上传一张最小合法 JPEG 测试图片，并在猫咪提交中引用，覆盖媒体所有权校验和媒体读取。

### 审计

必须至少出现 `ROLE_CHANGE`、`CREATE`、`UPLOAD`、`REVIEW`、`VISIBILITY`、`ARCHIVE`、`CLAIM` 七类动作。

## 安全、幂等与回滚

1. 生成前把 `/opt/help-cat/data/help-cat.db` 备份到带时间戳的 `/opt/help-cat/backups/` 目录。
2. 每次运行使用固定批次 `QA-20260801`；如果发现同批测试账号或实体已存在则停止，不叠加重复数据。
3. 把账号、会话、媒体文件和业务实体 ID 写入 `/opt/help-cat/data/qa/QA-20260801-manifest.json`。
4. 提供清理脚本，按审计、会话、配额、任务、猫咪、媒体、小区、测试用户的依赖顺序删除清单内数据；不按模糊名称删除。
5. 任何 API 步骤失败立即停止；测试数据生成完成后撤销 zack 临时会话。
6. 完成后断言 `SUPER_ADMIN` 恰好一个且用户名为 zack。

## 验收

- API 检查每个实体的预期状态和角色。
- 公开端只能看到 `ACTIVE` 小区、`APPROVED + ACTIVE` 猫咪和 `OPEN` 任务。
- 管理端 API 可以看到全部小区、全部猫咪和测试用户。
- 已领取任务不再出现在公开任务列表。
- 测试图片可以读取。
- 审计动作齐全，zack 唯一超级管理员不变。
- 生产健康检查与 Nginx 配置检查通过。
