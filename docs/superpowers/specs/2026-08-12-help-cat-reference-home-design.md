# 帮帮小猫确认稿首页设计规格

日期：2026-08-12  
状态：用户已用桌面/手机合成图确认，作为唯一视觉验收基准。

## 1. 目标

首页在桌面端与手机端严格复现确认稿的布局、层级、比例和交互，同时继续使用真实生产数据。设计稿中的数字和示例猫咪仅表达版式，不得作为线上假数据。

## 2. 已选方案

采用“同一语义 DOM + 桌面/手机响应式重排 + 后端成果台账”方案。

- 不复制两套页面，避免功能分叉和无障碍问题。
- 不从猫咪数量、任务标题推测救助成果，避免数据失真。
- 不写死设计稿数字；成果为空时显示 `0`。
- 新增可审计的成果事件台账，由管理员录入或撤销，公开端只读取聚合值。

替代方案未采用：

1. 纯静态仿图：视觉快，但数字虚假且无法运营。
2. 从现有 Cat/Task 状态推导：改动少，但“公开档案”不等于“已救助”，任务标题也不能可靠代表医疗或领养。

## 3. 视觉结构

### 桌面端（宽度大于 720px）

1. 76px 白色顶栏；左侧 77 标志和“帮帮小猫”，右侧依次为“77 的故事、需要帮助、猫咪档案、救助任务”。
2. 首屏为左右 50/50 的浅暖色区域；左侧宋体标题和橙色故事入口，右侧为完整、端正的 77 正脸。
3. 四项成果数据形成等宽横条：已救助、找到新家、医疗救助、爱心支持。
4. 内容区按 3:1 分栏；左侧四张猫咪档案卡，右侧一张救助任务卡。
5. 桌面端不显示悬浮底部导航。

### 手机端（宽度小于等于 720px）

1. 白色顶栏，左侧品牌，右侧两横线菜单。
2. 首屏使用手机专用 77 裁切；标题置于左侧，照片主体位于右侧。
3. 四项成果保持一行，使用紧凑图标、数字和标签。
4. 猫咪档案以两列展示四张卡；救助任务在其下方。
5. 固定底栏四项：“77 的故事、需要帮助、猫咪档案、救助任务”。

## 4. 数据与接口

新增 `impact_events` 表：

- `id`
- `kind`：`RESCUED`、`ADOPTED`、`MEDICAL`、`SUPPORTER`
- `amount`：正整数，默认 1
- `note`：内部说明
- `occurred_at`
- `created_by`
- `reversed_at`、`reversed_by`
- `is_qa`

管理员与超级管理员可新增、分页查看、撤销成果事件；普通用户无权写入。撤销保留记录，不物理删除。

`GET /api/v1/public/metrics` 返回：

```json
{
  "rescued": 0,
  "adopted": 0,
  "medical": 0,
  "supporters": 0
}
```

统计排除已撤销和 QA 数据，未登录与登录用户看到相同结果。

## 5. 首页数据规则

- 猫咪档案固定取公开接口最新四条；77 若存在则优先出现在首页首张，档案总页排序规则不改变。
- 卡片仅展示真实照片、昵称和公开城市/小区信息；图片失败时显示既有占位符。
- 救助任务取最新一条开放且非 QA 的任务；没有任务时保留相同尺寸的空状态卡。
- 网络失败时只在对应组件内部显示“暂时无法获取”，不在首屏顶部展示破坏布局的全宽错误条。

## 6. 错误与兼容

- 旧版三指标响应不再视为有效；前端要求完整四字段。
- 指标接口失败不阻断猫咪、任务和社区数据加载。
- 保留现有登录、建档、任务、社区审核、管理后台和 77 故事路由。
- iPhone 安全区、360px 小屏、768/1024px 平板和桌面宽屏均不得横向溢出。

## 7. 验收门禁

1. 后端单元测试覆盖四类聚合、QA 排除、撤销、权限和会话一致性。
2. 前端契约测试覆盖确认稿结构、四指标、四张首页卡、桌面隐藏底栏和手机导航文案。
3. 1440×900 与 390×844 本地截图逐项对比确认稿。
4. 发布后从 `https://helpcat.xyz/` 再取同尺寸截图；必须确认无错误条、真实数据加载、77 图片正确。
5. 全量 Python、Node、JS 语法、迁移实际执行和 `git diff --check` 全绿后才允许发布。
