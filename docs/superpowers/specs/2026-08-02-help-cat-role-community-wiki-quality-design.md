# Help Cat 角色、小区流程与 Wiki 质量整改设计

日期：2026-08-02

## 1. 背景与目标

本次整改解决三个直接影响生产可信度的问题：

1. 超级管理员在已打开的旧 H5 页面中仍被显示为志愿者，并看不到管理后台入口。
2. 小区新增能力虽然已经存在，但入口、文案和审核规则不够清楚，用户不知道从哪里新增小区。
3. 项目缺少面向持续迭代的 Wiki，后续无法快速判断现有能力、未实现能力、架构边界和上线风险。

用户明确要求项目按照未来接入微信小程序、服务大量用户的标准推进。本次不直接把单机 MVP 一次性改造成分布式系统，而是先修复当前业务流程、提高版本可感知性，并在 Wiki 中给出可执行的规模化演进路线和上线门槛。

## 2. 根因与现状证据

### 2.1 超级管理员显示错误

- 生产数据库中 `zack` 的角色为 `SUPER_ADMIN`，状态为 `ACTIVE`，且是唯一超级管理员。
- 生产 `/api/v1/auth/me` 返回 `id`、`username` 和 `role`，后台鉴权同时接受 `ADMIN` 与 `SUPER_ADMIN`。
- 生产静态资源已经包含 `SUPER_ADMIN` 文案和“进入管理后台”按钮。
- 用户当前标签页在刷新前仍运行部署前的 JavaScript。旧逻辑只判断 `role === "ADMIN"`，因此把 `SUPER_ADMIN` 显示为志愿者。
- 刷新页面后，现场 DOM 已显示“超级管理员账号 · 新建档案将直接公开”和“进入管理后台”。

因此账号数据和后端权限没有损坏；直接根因是长时间打开的页面继续运行旧前端实例。现有资源版本参数只能保证下一次加载取新文件，不能主动通知已经打开的旧页面。

### 2.2 小区流程不清晰

现有能力如下：

- H5 “我的”页底部有“没有找到小区？”表单。
- 普通用户提交后状态为 `PENDING_REVIEW`，需要管理员审核。
- `ADMIN` 或 `SUPER_ADMIN` 调用同一接口时，小区直接变为 `ACTIVE`。
- 管理后台“小区管理”页已有新增表单，管理员新增后立即开放。
- 管理后台会列出所有小区，并允许审核待审小区或归档小区。

当前问题不是缺少后端功能，而是：

- 创建猫咪流程只显示“请选择已审核小区”，没有明显说明找不到时去哪里新增。
- H5 小区表单对所有角色都显示“提交建议/等待审核”语义。
- 提交成功提示仅判断 `ADMIN`，`SUPER_ADMIN` 会收到错误的“等待审核”提示，即使后端已经立即开放。
- 管理后台流程没有在用户端和文档中被清晰串联。

## 3. 方案比较

### 方案 A：角色感知的统一小区入口（采用）

保留同一个创建接口和现有权限规则，在 H5 根据角色切换标题、说明、按钮和成功提示；在创建猫咪第二步增加显眼的小区入口；管理后台继续承担批量查看、审核和归档。

优点：复用成熟接口，改动集中，普通用户和管理员都能理解同一条流程，风险低。

### 方案 B：只在管理后台允许新增小区

从 H5 移除普通用户建议能力，所有小区由管理员创建。

优点：治理最严格。缺点：大量社区扩展时管理员成为瓶颈，不适合用户共同参与的救助产品。

### 方案 C：在猫咪表单内直接内嵌完整小区创建

找不到小区时直接在三步猫咪表单中展开新小区字段。

优点：路径最短。缺点：一个提交同时涉及小区审核和猫咪审核，失败恢复、状态解释和数据关联更复杂。

采用方案 A。它保持“小区先成立、猫咪再关联”的清晰数据边界，也保留社区共建能力。

## 4. H5 交互设计

### 4.1 角色展示与管理入口

- `USER`：显示“志愿者账号 · 可提交档案并领取任务”，不显示后台入口。
- `ADMIN`：显示“管理员账号 · 新建档案将直接公开”，显示“进入管理后台”。
- `SUPER_ADMIN`：显示“超级管理员账号 · 新建档案将直接公开”，显示“进入管理后台”。
- 进入后台前，将当前 H5 Bearer Token 写入管理后台现有的同源 `sessionStorage` 键，然后导航到 `/help-cat/admin/`。
- 后台仍调用 `/api/v1/auth/me` 重新校验角色；前端按钮不是权限边界。

角色比较统一通过一个规范化函数完成，避免大小写或空值导致错误展示。后端数据库仍以大写角色值为唯一标准。

### 4.2 小区新增入口

创建猫咪第二步在小区选择框下增加一个清晰操作：

- 普通用户看到“没有找到小区？提交小区建议”。
- 管理员和超级管理员看到“没有找到小区？新增并开放小区”。

点击后保留当前猫咪表单内容，关闭建档弹层，进入“我的”页并聚焦小区表单。用户完成小区创建后，公开小区列表立即刷新；管理员可以返回建档继续选择刚创建的小区。

### 4.3 角色感知的小区表单

普通用户：

- 标题：没有找到小区？
- 说明：提交建议后由管理员审核，审核通过后可用于猫咪档案。
- 按钮：提交小区建议。
- 成功提示：小区建议已提交，等待管理员审核。

管理员与超级管理员：

- 标题：新增小区。
- 说明：新增后立即开放，可直接用于猫咪档案。
- 按钮：新增并开放。
- 成功提示：小区已创建并开放。

### 4.4 版本更新提示

- 在 HTML 中暴露明确的应用版本标记。
- 页面在首次加载、重新获得可见状态时，以 `cache: "no-store"` 请求当前 HTML 并比较版本。
- 发现服务器版本更新时，在不清空表单的前提下显示固定更新提示，由用户点击刷新。
- 不自动强制刷新，避免用户正在填写猫咪档案或上传照片时丢失输入。
- 静态资源继续使用版本查询参数，HTML 由 Nginx 配置为不缓存或必须重新验证。

## 5. 小区业务与审核流程

```text
普通用户提交小区
  -> PENDING_REVIEW
  -> 管理后台“小区管理”
  -> 管理员/超级管理员审核
     -> 通过：ACTIVE，可被猫咪档案选择
     -> 不通过：HIDDEN，不对公众开放

管理员/超级管理员新增小区
  -> ACTIVE
  -> 立即进入公开小区列表
  -> 可直接创建猫咪档案

管理员归档小区
  -> ARCHIVED
  -> 不再出现在公开选择列表
```

所有创建、审核、修改和归档继续写入 `audit_logs`。普通用户不能调用审核、编辑和归档接口。

## 6. GitHub Wiki 信息架构

Wiki 采用多页面结构，作为项目的持续迭代手册：

1. `Home`：产品目标、当前状态、线上入口、文档导航。
2. `功能清单与状态`：按 H5、管理后台、后端、小程序列出已实现、部分实现、未实现。
3. `系统架构`：当前组件图、目录结构、请求链路、鉴权方式、部署拓扑。
4. `角色与权限`：USER、ADMIN、SUPER_ADMIN 权限矩阵和不可越权规则。
5. `核心业务流程`：登录、小区、猫咪、任务、图片上传、管理员赋权流程。
6. `数据模型与 API`：核心表、状态机、API 分组和错误语义。
7. `部署、回滚与运维`：服务器目录、systemd、Nginx、发布、哈希、备份和回滚。
8. `测试与质量保障`：自动化范围、生产验收、测试数据、已知限制。
9. `微信小程序接入`：现有 miniapp 骨架、域名/HTTPS/合法域名要求和待办。
10. `规模化路线图`：从当前 MVP 到几十万用户的容量、安全和治理演进。
11. `变更记录`：按日期记录重要功能、缺陷、部署版本和 PR。

Wiki 不记录密码、Token、私钥、真实个人联系方式或精确猫窝位置。

## 7. 当前架构的规模边界

当前生产架构是单机 FastAPI + SQLite + 本地图片目录 + Nginx 静态资源，适合验证业务闭环和早期社区试运行，但不能宣称已经具备几十万用户容量。

规模化路线分阶段执行：

1. 域名、HTTPS、微信小程序登录、隐私政策、用户协议和账号注销先满足正式上线要求。
2. SQLite 迁移 PostgreSQL；迁移过程具备备份、校验和回滚。
3. 图片迁移对象存储并通过 CDN 分发，增加内容审核、EXIF 清理和生命周期策略。
4. 会话、限流与热点数据迁移 Redis，服务改为可水平扩展的无状态实例。
5. 异步通知、图片处理和审核任务使用消息队列。
6. 建立日志、指标、链路追踪、告警、备份恢复演练和容量压测。
7. 增加防刷、防重复档案、敏感位置保护、举报、封禁和内容治理。

每一阶段都在 Wiki 中列出进入条件、验收指标和回滚方式，未达到时明确标记为“未实现”。

## 8. 错误处理与兼容性

- 角色缺失或未知时按最小权限 `USER` 展示，不显示管理入口。
- 后台入口可见但 Token 失效时，后台回到登录页，不绕过鉴权。
- 小区创建冲突显示“已经存在或正在审核”，保留表单输入。
- 普通用户提交的小区未审核前不能被猫咪档案选择。
- 页面检测到新版本只提示刷新，不自动丢弃输入。
- H5 在手机、平板和桌面断点下保持按钮可见、表单不横向溢出。

## 9. 测试与验收

### 自动化

- 后端：USER 建议待审；ADMIN 和 SUPER_ADMIN 新增后立即 ACTIVE；只有管理员可审核/归档。
- H5 合同：两种管理员角色显示入口与正确文案；普通用户不显示；创建猫咪页存在小区快捷入口；版本标记和更新提示存在。
- 管理后台：小区新增、待审列表、审核、归档接口和超级管理员权限管理保持可用。
- 全量回归：现有 33 项测试、JavaScript 语法检查和 `git diff --check`。

### 生产验收

- 使用 `zack` 恢复会话后显示超级管理员文案和后台入口。
- 点击后台入口后进入 `/help-cat/admin/` 且无需再次输入密码。
- 超级管理员从 H5 和后台分别新增测试小区，状态均立即为 ACTIVE。
- 普通测试用户提交小区后为 PENDING_REVIEW，管理员审核后进入公开列表。
- 手机、平板、桌面验证无横向滚动，版本更新提示不遮挡主要操作。
- 发布前备份，上传后比较本地、release、生产 SHA-256；任一关键验收失败立即回滚。

## 10. 非本次实现范围

- 本次不直接迁移 PostgreSQL、Redis、对象存储或消息队列。
- 本次不开放普通用户直接发布 ACTIVE 小区。
- 本次不改变唯一超级管理员规则。
- 本次不完成微信正式登录、域名备案、HTTPS 证书和小程序审核；这些进入 Wiki 路线图并在域名就绪后单独实施。
