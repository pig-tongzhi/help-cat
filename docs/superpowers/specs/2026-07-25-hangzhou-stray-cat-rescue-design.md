# 杭州银湖街道流浪猫救助 H5 设计

## 目标

为个人救助者提供一个可在手机浏览器使用的救助台账，覆盖投喂点、猫咪档案、受伤上报、TNR 状态、志愿者任务、物资短缺、操作日志和数据导出。首个试点限定在杭州市富阳区银湖街道，后续可扩展到区、街道、小区层级。

## 设计决策

- 地图是位置辅助，不是精确猫窝公开地图。
- 公开端只显示“银湖街道 + 小区/道路级”或模糊点；精确坐标仅管理员可见。
- 没有地图 Key 时，使用手工选择的街道/小区和演示坐标，不阻塞核心业务。
- 首版不做募捐、支付、领养交易、摄像头、AI 个体识别和实时聊天。
- 单体 H5 优先，地图服务通过适配器封装；未来微信小程序复用同一 API 和数据模型。
- 失败上报不得产生猫咪档案、任务、库存或其他业务副作用。

## 页面与主流程

1. 首页：银湖街道统计、公开投喂点、待处理救助事项。
2. 投喂点：新增/编辑点位，查看猫咪、物资和近期记录。
3. 猫咪档案：编号、昵称、性别、毛色、照片说明、TNR 和健康状态。
4. 上报：受伤、异常、疑似走失、物资短缺；提交后进入待审核。
5. 任务：管理员将审核通过的事项转为任务；志愿者认领、更新、完成并上传证据描述。
6. 日志/导出：按时间、类型和操作者查询，导出 CSV/JSON。

## 安全与隐私

- 不允许公开完整住址、门牌、投喂者联系方式和猫窝精确坐标。
- 公开展示前需经过审核状态和字段脱敏。
- 所有创建、修改、审核、认领、完成、导出操作写入不可编辑日志。
- 前端演示数据不代表真实救助事实，正式上线前需替换并由管理员核验。

## 地图策略

- `MapProvider` 提供 geocode、reverseGeocode、placeSearch、maskLocation、navigationUrl 五个能力。
- 首选高德 Web 服务 API；Key 只放服务端环境变量，不进入前端代码。
- 小程序阶段可增加腾讯位置服务适配器，适配微信地图组件和地点选择。
- 业务数据保存行政层级和模糊位置，地图响应只作为辅助，不改变业务状态。

## 验收原则

所有关键流程必须验证正向、反向、权限、幂等、位置脱敏、数据库前后变化和导出内容；独立验收不采信 AA 的口头结论。
