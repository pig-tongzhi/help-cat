# 帮帮小猫 H5 猫咪卡片响应式优化设计

## 目标

修复猫咪卡片在生产 H5 中出现的破图文字、空白图片区、徽标裸露、正文失去排版和卡片过高问题；同一套组件自动适配桌面、平板和手机，不提供手动布局开关。

## 根因

1. `app/rescue/app.js` 输出 `cat-card-body`、`cat-title`、`cat-placeholder`、`health-badge` 等类名，而 `styles.css` 仍定义旧版 `cat-body`、`cat-photo-placeholder`、`cat-status` 等选择器，导致大部分卡片样式没有命中。
   同一次命名漂移也影响任务卡的 `task-priority`、`task-copy` 和提交记录的 `submission-type`、`review-status`，本次一并恢复这些 H5 区块的组件契约。
2. 线上 `[QA-20260801]` 测试图片只有 19 字节，只满足服务端 JPEG 文件头检查，不是浏览器可解码的完整图片，因此 `<img>` 显示破图图标和 alt 文本。
3. 图片失败时没有运行时回退，浏览器原生破图内容覆盖在图片区；无图片卡片虽然插入占位节点，但占位节点没有对应样式。
4. 当前响应式只改变列数，没有针对手机调整卡片结构，单列卡片仍保留大比例图片区，滚动距离过长。

## 方案比较

### 方案 A：只增加 CSS 别名

为新类名补一组样式，改动最小，但破图仍然存在，移动端仍然是大图堆叠，后续 JS/CSS 容易再次漂移。

### 方案 B：统一组件契约并重构响应式（采用）

保留当前语义更清晰的 JS 类名，以其为唯一组件契约；重写猫咪卡片样式、增加图片错误回退、为健康状态添加视觉变体，并分别优化桌面、平板、手机布局。改动集中在猫咪卡片组件，风险可控。

### 方案 C：引入 UI 框架重写页面

可以统一组件体系，但会显著扩大体积、构建和回归范围，不适合当前原生 HTML/CSS/JS 项目。

## 卡片组件

每张卡片保持以下层次：

1. 媒体区：真实照片或统一猫咪插画占位；右上角显示健康状态胶囊。
2. 标题区：猫咪名称为主标题，档案编号为弱化信息。
3. 归属区：小区名称，使用位置图形和单行截断。
4. 元信息区：居住情况和模糊活动位置，限制两行，避免长文本撑高卡片。

图片节点和占位节点同时存在。正常加载时照片覆盖占位；`error` 事件由全局捕获监听器处理，隐藏失败图片并给媒体区增加 `image-failed`，绝不显示浏览器原生破图文本。无照片直接显示占位。

健康状态映射：

- `HEALTHY`：绿色“状态良好”。
- `NEEDS_HELP`：橙色“需要关注”。
- `UNKNOWN`：中性灰绿色“待观察”。

## 自动响应式布局

### 桌面（宽度大于 1024px）

- 内容区最多 1180px，猫咪档案三列。
- 图片比例 `16:10`，卡片正文统一高度，名称和位置受行数限制。
- 首页最多展示三张，完整档案页展示全部。

### 平板（721–1024px）

- 自动切为两列，间距和内边距缩小。
- 图片保持稳定比例，文字字号不低于 12px。
- 底部导航宽度随视口变化，确保横竖屏都无横向滚动。

### 手机（不大于 720px）

- 自动切为单列横向卡片：左侧 118–132px 媒体，右侧信息。
- 健康徽标缩小但保持可读；名称最多两行，位置最多两行。
- 无图插画在小媒体区居中，不保留大面积空白。
- 360px 以下进一步压缩图片宽度和卡片内边距。
- 保留底部安全区和 44px 最小点击区域。

## 数据修正

备份当前 QA 媒体文件后，用一张完整、可解码的测试猫咪 JPEG 替换相同 `object_key` 文件；不修改媒体 ID、猫咪关联或真实业务数据。页面仍必须正确处理无图和未来损坏图片，不能依赖本次数据修正掩盖问题。

## 测试与上线

- 契约测试校验 JS 输出类名与 CSS 选择器一致，并存在图片 `error` 回退监听。
- 现有 105 项应用测试和 12 项后端测试保持通过。
- 本地隔离 API 使用生产 QA 数据结构进行浏览器回归。
- 桌面 `1440×900`：三列、无破图、无横向溢出。
- 平板 `820×1180`：两列、导航和筛选完整、无横向溢出。
- 手机 `390×844`：单列横向卡片、无大空白、底部导航不遮挡内容。
- 图片正常、无图片、加载失败三种情况都必须显示合理。
- 上线前备份 `app/rescue` 静态文件和 QA 媒体文件；上线后通过公网直连复核版本、服务健康和页面资源。
