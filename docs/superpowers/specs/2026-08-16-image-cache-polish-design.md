# 图片与缓存体验优化设计

## 目标

在不改变现有业务接口、数据库、部署拓扑或登录流程的前提下，让 H5 与微信小程序在移动网络中稳定、完整地展示猫咪照片与 77 故事图片，并降低重复图片下载与手机原图上传带来的等待。

## 范围

本次仅实施图片与缓存体验优化（方案 A）。保留现有 WebP 缩略图、媒体 ID 与原图 URL；不引入 CDN、对象存储、Redis、数据库迁移或服务端并发扩容。

## H5 设计

猫咪列表继续优先请求 `?variant=thumb` 缩略图。每张图片保留明确的宽高或容器比例、`loading="lazy"` 与 `decoding="async"`；首屏关键图不延迟加载。缩略图失败时只回退请求一次原图，原图也失败时显示既有占位内容，且不保留浏览器破图图标。

77 故事图片保持完整展示和暖白背景；失败状态显示可点击的“重新加载照片”按钮，该按钮仅重试当前原始 URL 并添加缓存破除参数。

静态图片、缩略图与原图使用现有的一年 `immutable` 缓存头。HTML 通过已存在的发布版本号引用可变资源，发布新版本时不依赖用户清理浏览器缓存。

## 微信小程序设计

列表页只使用媒体缩略图 URL，并保留固定图片区域，避免图片加载后挤动卡片。图片加载失败显示应用内占位状态，不向用户暴露裂图；下拉刷新会重新拉取列表数据。

上传猫咪照片前，在客户端将可压缩图片限制为适合网络提交的尺寸与质量，并保留原有的 JPEG、PNG、WebP 类型限制。上传失败必须保留用户已填表单和已选照片路径，并给出可重试提示；不改变服务端的文件大小、像素安全检查。

## 兼容性与错误处理

任何缩略图优化都不得改变原图接口的可用性。老媒体没有缩略图时仍由服务端按需生成。前端图片出错不得重复无限请求；每次加载最多进行一次原图回退或一次用户主动重试。

## 验收

- 服务端测试证明缩略图和原图均返回一年不可变缓存头，且缩略图不改变原媒体 ID。
- H5 契约测试证明列表图片具有懒加载、异步解码与一次原图回退；故事图具有明确失败和重试状态。
- 小程序契约测试证明列表使用缩略图、图片区域固定，上传前调用压缩能力并保留失败状态。
- 现有 Python、Node/JavaScript 契约测试、语法检查与 `git diff --check` 均通过。

## 非目标

- 不新增 CDN、腾讯 COS、Redis、消息队列或监控平台。
- 不迁移 SQLite 到 PostgreSQL。
- 不修改公开 API 的响应结构、鉴权规则或业务审核流程。
