# 变更记录

## 2026-09-24：安全加固（关后门 + 登录限速 + 关 API 文档 + 安全响应头）

状态：已上线，release `20260924-security-hardening-r21`，版本 `20260923-product-r13`。起因是做了一次实测安全体检，以下四条是其中的"可立刻做、零功能影响"部分。

- **关掉"万能登录"后门**：`fake:` 开头的 code 原来**无条件**换会话。线上没配微信凭据，等于任何人发一个 JSON 就能用任意 openid 建号（实测已复现）。现在只有显式设了 `HELPCAT_ALLOW_FAKE_WECHAT=1` 才认（本地开发与测试用 `conftest.py` 打开，生产不设即为关）。H5 本来就没有微信登录入口，用户无感。
- **密码登录限速**：原来连试 6 次错误密码全是 401，没有 429、没有锁定。现在按**账号**（默认 15 分钟 10 次）和**来源 IP**（15 分钟 30 次）两条线计数，超限返回 `too_many_login_attempts`；**成功登录即清零**，避免把自己锁在外面。计数落在新表 `login_attempts`（迁移 `012`，带索引）—— 单独一张表而不是写审计，因为审计的 `actor_id` 有外键、失败的登录可能连账号都不存在。触发限速后不再写新行，表不会被刷爆。
- **API 文档默认关闭**：`/docs`、`/redoc`、`/openapi.json` 之前全部公开（200），把接口与字段清单连同所有后台接口都摊给外人看。现在默认 404，本地要看设 `HELPCAT_EXPOSE_API_DOCS=1`。
- **安全响应头**：全站原来**一个都没有**。新增 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`、`Content-Security-Policy`。落地方式是 `deploy/nginx/helpcat-security.inc` —— nginx 的 `add_header` 只在子级自己没有任何 `add_header` 时才继承父级，而我们多个 location 写了 `Cache-Control`，所以逐个 include（含 IP 入口里 help-cat 的那几个 location，**没有碰同机另一个项目**）。
  - CSP 口径按前端实际能力定：`script-src 'self'`（三个页面都没有内联脚本、内联事件处理器和 `eval`）、`style-src 'unsafe-inline'`（H5 有一个内联 `<style>`）、`img-src blob:`（选照片预览用 `createObjectURL`）、`connect-src 'self'`。
  - 验证：三个页面的浏览器日志里 **0 条 CSP 拦截**，H5 猫卡、77 故事、后台标题、欢迎页都由 JS 正常渲染。
- 体检里**未处理**的（需要你拍板）：SSH 允许 root 密码登录且已被暴力尝试 29,606 次、全站明文 HTTP（可选方案：给 IP 签 Let's Encrypt 证书，无需备案）、备份未加密且机器上另一个账号可读。

## 2026-09-24：大图自己压缩，照片失败不再挡住建档

状态：已上线，release `20260924-image-downscale-r18`，版本 `20260923-product-r10`。

用户反馈「图片像素过大」太影响体验。原来后端默认 **5MB / 24MP**，nginx 另有一道 10MB —— 手机 48MP 照片（8000×6000）必然撞上像素上限，而且**照片传失败整个档案就建不出来**。现在四层一起改：

- **后端自己缩**：长边超过 `HELPCAT_IMAGE_MAX_SIDE`（默认 1600）就缩小后再存，不再拒绝。JPEG/MPO 先用 `Image.draft` 让解码器直接吐缩小后的位图，不必为缩放先解出整张原图（48MP 照片 0.16s / 20KB 落库）。`max_image_pixels` 从 24MP 提到 **120MP**，只当解压炸弹的硬上限；`max_image_bytes` 从 5MB 提到 **20MB**。
- **多帧不再按帧数乘像素**：MPO 以前会把帧数算进像素总数，正常照片被推过上限；现在只解码第一帧，落库也统一是单帧。
- **前端先压一道**：`api.uploadImage` 会在浏览器里把图缩到长边 1600、转 JPEG（质量 0.86）再上传，压不动（HEIC、老浏览器、canvas 出错）就退回原图交给后端。
- **照片失败不挡建档**：建档与投喂打卡都会在照片上传失败时照常提交，并提示「照片没传上去，可以发给管理员补上」；不再因为一张图丢掉整份记录。
- **不再对用户说「像素」**：`image_too_large` / `image_too_many_pixels` 的文案改成「这张照片太大，没处理成功。可以先截图再上传。」，后端那条也一并去掉像素字眼。
- nginx 两套入口的接口与素材上限同步提到 20MB（`deploy/nginx/*.conf` 已更新并 reload）。
- 新增测试：12MP 照片缩到 1600×1200、竖图保持方向、只有炸弹被拒且文案不含「像素」、多帧不按帧计数、前端压缩与失败兜底（pytest 契约 + 无 canvas 环境退回原图）。
## 2026-09-24：修手机照片被误判为「图片内容无法识别」

状态：已上线，release `20260924-mpo-upload-r17`，版本 `20260923-product-r9`。

- **根因**：白名单只认 JPEG / PNG / WEBP，而**手机相机的 HDR / 人像 / 连拍照片常常是 MPO** —— 它本质就是带多帧的 JPEG，但 Pillow 把 `format` 报成 `"MPO"`，于是被当成"不认识的格式"，返回 `image_content_mismatch`，前端显示「图片内容无法识别」。已在本地用合成 MPO 复现。
- **修法**：解码后先把 MPO 归一化成 JPEG 再查白名单、走重编码分支（否则字节会被存成 WebP 而 `content_type` 报 image/jpeg，浏览器渲染不出来 —— 第一版就踩了）。落库统一压成**单帧** JPEG，缩略图照常生成。
- **顺带放宽两类真实情况**：`image/jpg` 这类非标准 MIME 视同 `image/jpeg`；选择器**不给 MIME**（空串 / `application/octet-stream`，部分安卓与微信会这样）不再前端拦掉，改由解码结果判断。
- **报错说得清**：真不支持的格式（GIF / HEIC / AVIF…）返回新的 `unsupported_image_format`，并写明"这张实际是 X 格式"，而不是笼统的"无法识别"；前端预检也改成报出实际 MIME 并提示"iPhone 的 HEIC 可以先截图再上传"。
- 新增 `server/tests/test_media_upload_formats.py`（11 项）：MPO 收下且落成单帧 JPEG、别名与空 MIME 收下、PNG 冒充 JPEG 仍然拒、GIF 报出真实格式、明确声明的 image/heic 在入口挡掉、缩略图生成。
- 欢迎页称呼字段的提示文字「不填就叫你「喜猫人」」按要求去掉（后端的留空默认值保留）。
