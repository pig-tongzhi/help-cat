# 测试与质量保障

## 自动化测试结构

### 后端 API

`server/tests/test_commercial_api.py` 使用临时数据库和真实 FastAPI 应用验证：

- 注册、登录、会话恢复与退出。
- USER、ADMIN、SUPER_ADMIN 权限边界。
- 唯一超级管理员不可修改。
- 普通用户小区待审、管理员小区直接开放。
- 候选名称规范化、创建者修改、权限拒绝、版本冲突、显式审核状态机。
- 候选与猫咪原子创建、失败回滚、合并改挂和发布拦截。
- 候选驳回后的单猫改挂恢复、改挂目标校验和猫咪版本冲突。
- 幂等建档重试返回原记录，不重复创建候选、不重复扣每日配额。
- 有效小区名称数据库唯一性和终态后正确重建。
- 猫咪、小区、任务、本人提交和用户游标分页。
- 后台服务端关联总数和最多 3 条预览。
- 两个真实数据库会话并发更新同一小区时，第二个事务由版本谓词拒绝。
- 管理员 Session 撤销后不能再读取待审猫咪，公开/管理员双视图不会绕过 `revoked_at`。
- 猫咪每日配额、审核和可见性。
- 任务领取竞争状态。
- 图片类型、大小、签名和所有权。

### 前端合同

- `tests/test_rescue_h5_contract.py`：H5 页面结构、内联候选/纠错、分页、角色入口、响应式断点、图片选择、版本提示、页脚和静态资源顺序。
- `tests/test_commercial_frontends.py`：后台首页返回、联审动作、分页、高级响应式视觉、权限入口和 API 路由合同。

### 前端行为

- `tests/js/admin_session_runtime.test.js`：真实执行后台退出，验证服务端注销请求、双 Token 清理、网络失败和防重复点击。
- `tests/js/rescue_version_runtime.test.js`：真实执行版本比较，验证同版本、新版本、非 2xx、无版本标记和网络失败。
- `tests/js/rescue_community_runtime.test.js`：建档小区二选一 payload、纠错版本、状态元数据和分页去重。
- `tests/js/admin_community_review_runtime.test.js`：核准/退回/合并/驳回请求、必填理由、版本和分页去重。

### 数据与迁移

- `tests/test_commercial_migrations.py`：数据库结构、mapper 原子版本竞争和真实 Alembic 旧库升级；未安装 Alembic 的系统 Python 会跳过真实升级用例，生产/CI 依赖环境必须执行。
- `tests/test_help_cat_qa_seed.py`：QA 数据可重复生成。
- `tests/test_help_cat_qa_cleanup.py`：QA 数据清理范围和预览安全。

## TDD 要求

每个新功能和缺陷修复遵循：

1. 写一个能够复现缺口的最小测试。
2. 运行并确认测试因预期原因失败。
3. 实现最小修改。
4. 运行聚焦测试变绿。
5. 运行完整回归，确认没有破坏其他流程。
6. 独立提交，便于审查和回滚。

## 生产 QA 数据

项目包含生产 QA 数据生成和清理脚本。QA 数据使用明确命名空间，覆盖：

- 普通用户、管理员。
- ACTIVE、PENDING_REVIEW、HIDDEN、ARCHIVED 小区。
- 已通过、待审核、未通过和隐藏猫咪。
- 开放与已领取任务。
- 图片正常、占位和异常加载场景。

生成前备份数据库；清理脚本默认预览，只允许清理 manifest 中记录的 QA 实体，不能按宽泛前缀删除真实数据。

## 上线验收矩阵

| 场景 | 预期 |
|---|---|
| USER 登录 | 显示志愿者文案，无后台入口 |
| ADMIN 登录 | 显示管理员文案，有后台入口 |
| SUPER_ADMIN 登录 | 显示超级管理员文案，有后台入口 |
| 后台快捷入口 | 无需再次输入密码进入后台；失效 Token 回登录页 |
| USER 建档内填写新小区 | 候选与猫咪同时成功或同时失败，共享 community_id |
| USER 新增小区 | PENDING_REVIEW，不出现在公开选择 |
| 创建者修改候选 | 仅本人待审/待补充可改，过期 version 返回 409 |
| 管理员退回候选 | 必填理由，变 NEEDS_CHANGES，关联猫咪保持待审 |
| 管理员合并候选 | 目标必须 ACTIVE，关联猫咪全部事务改挂 |
| 管理员驳回候选 | 关联猫咪仍可搜索 ACTIVE 小区、单只改挂并继续审核 |
| 网络丢包后重试建档 | 相同 Idempotency-Key 返回原猫咪，只扣一次配额 |
| 小区未开放时审核猫咪 | 返回 community_not_active，公开列表也不可见 |
| ADMIN/SUPER_ADMIN 新增小区 | ACTIVE，立即可选 |
| 小区审核通过 | 进入公开列表 |
| 手机选择照片 | 可选择相册或拍摄，不强制后置相机 |
| 旧页面遇到新版本 | 显示更新提示，不清空表单 |
| 普通猫咪提交 | 待审核且每日配额生效 |
| 管理员猫咪提交 | 直接 APPROVED |
| 生产健康和哈希 | API 正常，静态文件与 release 一致 |
| 双端页脚 | 精确显示“安得广厦千万间，大庇天下小猫俱欢颜” |

## 设备与浏览器

最低回归覆盖：

- 360 px 小屏手机。
- 390/430 px 主流手机。
- 768/820 px 平板。
- 1024 px 横屏平板/小桌面。
- 1280 px 及以上桌面。

重点检查横向溢出、底部导航、安全区、弹层滚动、键盘遮挡、图片选择、长文本和无图片状态。

## 已知质量缺口

- 当前前端测试以合同测试为主，缺少完整的端到端浏览器测试套件。
- 应用内浏览器自动化曾受外部遥测网络超时影响，不能用工具超时替代产品结果判断。
- 没有持续集成工作流自动运行测试。
- 浏览器自动化需在生产 HTTPS/域名完成后纳入 CI；当前会在每次部署后做真实入口多视口验收。
- 没有性能、容量、故障注入、无障碍扫描和安全扫描流水线。
- 没有生产 SLO 和错误预算。

进入大规模推广前应把这些项目转为自动门禁，而不是依赖人工记忆。
