# 流浪猫投喂救助 App 调研

## 调研目标

在 4 核、4G 内存、3M 带宽的云服务器上，设计一个先能运行、面向真实救助协作的轻量 App。第一版不做复杂 AI、不做视频、不托管大量原图、不急于接入募捐支付。

## 已有方案与可借鉴点

### 1. 宠物帮救助平台

提供寻宠、拾宠寻主、救助和领养信息发布，支持微信和抖音小程序，强调免费、无需下载和信息扩散。

可借鉴：低门槛入口、案件发布、寻主/领养信息结构化、移动端优先。

不足/差异点：公开介绍主要集中在信息发布和匹配，没有突出投喂点日常任务、TNR 状态、伤病处置和救助过程审计。

来源：https://www.petadopt.cn/

### 2. 哈啰街猫

通过 App 与智能设备云联动，提供云投喂、云吸猫、云监控，并组织 TNR 小组；其链路是“智能监控 → 合理处置（TNR/领养）→ 长效管理”。

可借鉴：把单次投喂提升为持续管理，围绕投喂点、监控和绝育建立闭环。

不足/差异点：依赖硬件和品牌体系。我们的 MVP 应先支持人工签到和照片证据，不采购智能猫屋。

来源：https://www.hellostreetcat.com/

### 3. StrayDash

面向救助站，直接拆成三个模块：投喂点、绝育记录、受伤上报；支持地图、志愿者任务、开放链接、照片、审计日志、数据导出和影响统计。

可借鉴：模块划分非常接近实际工作流；“谁发现、谁处理、何时关闭、留下什么证据”比单纯发帖更有价值。

来源：https://straydash.com/

### 4. 浪途

支持发现幼猫、流浪动物、受伤动物、安置和送养等情况的线上通报，并强调每个案件可以持续追踪。

可借鉴：把一次求助变成可追踪案件，而不是在群聊里沉没。

来源：https://shop.noramichi.app/about

## 真实痛点假设

1. 投喂者不知道附近是否已经有人喂，容易重复投喂、留下卫生问题或引发邻里冲突。
2. 猫的数量、花色、绝育/剪耳、健康状态和固定活动点没有统一记录。
3. 受伤、绝育、送医、放归和领养状态分散在微信群和个人相册，后续无法追踪。
4. 志愿者不知道今天哪些点需要去、哪些任务已被接单、哪些物资短缺。
5. 公众愿意帮忙，但缺少低风险、可验证的参与方式；直接收款又容易产生信任和合规问题。
6. 救助组织需要证明物资、医疗和绝育的去向，但第一版不应自行承诺公益募捐资质。

## 机会定位

不是“猫咪照片社区”，而是：

> 面向一个小区/街道/校园的流浪猫救助协作台账：投喂点、猫咪档案、TNR、伤病案件、志愿者任务和证据记录。

## MVP 功能建议

### 公共侧

- 查看附近公开投喂点和救助案件。
- 扫描投喂点二维码查看今日是否已投喂、是否缺粮、是否有异常。
- 上报流浪猫、受伤、走失、需要绝育等事件。
- 查看领养状态和联系入口。

### 救助者侧

- 创建投喂点和猫咪档案。
- 记录投喂、饮水、清洁、发现异常。
- 建立 TNR 状态：待观察、待诱捕、已绝育、恢复中、已放归。
- 接收/认领任务，上传照片和备注。
- 关闭案件前必须填写结果和证据。

### 管理侧

- 审核公开上报，隐藏精确住址和敏感信息。
- 查看任务、案件、绝育和物资统计。
- 操作日志和 CSV/JSON 导出。

## 明确不做

- 第一版不接募捐、分账或提现。
- 不公开精确猫窝位置，避免骚扰、盗捕和恶意伤害。
- 不做自动识别猫咪品种/个体的 AI 承诺。
- 不做智能猫屋、摄像头、IoT 设备接入。
- 不做全国开放平台，先限定一个小区/校园/街道组织。

## 服务器可行性

4 核 4G 3M 足够支撑第一版单体服务：前端静态资源 + Python/Node API + SQLite/PostgreSQL。图片不应全部存本机，建议限制压缩图尺寸、设置单文件上限，并预留对象存储或图床适配接口。地图第一版使用经纬度网格/列表，不加载重型地图瓦片；公开端做缓存，后台任务采用轻量定时器。

## 风险与防护

- 位置风险：公开端只显示模糊区域；精确坐标仅授权救助者可见。
- 虚假信息：上报先进入待审核；公开前需要照片、描述和来源。
- 人身/动物安全：受伤案件提示联系正规动物医院或当地相关部门，不提供远程医疗结论。
- 资金风险：第一版不代收善款，不显示“捐款入口”；物资需求只做登记。
- 领养风险：领养申请需要人工审核和线下核实，平台不替代双方责任。
- 隐私风险：联系方式不公开展示，使用站内联系或脱敏信息。

## 推荐方案

借鉴 StrayDash 的“投喂 + TNR + 伤病”模块、浪途的“案件追踪”、宠物帮的“低门槛发布”，做一个本地化的“救助协作台账”。第一版核心闭环只有：

`上报 → 审核 → 认领任务 → 上传证据 → 关闭案件`

等一个真实救助组织连续使用后，再决定是否增加领养匹配、物资商城、志愿者积分或合规公益合作。
